# Deadly Dungeon 🏰

เกมบอร์ด "Deadly Dungeon" เล่นหลายคนผ่านเว็บ (สูงสุด 6 คน) — ดันเจี้ยนสุ่มที่ซ่อนเลขห้องลึกลับ
เดินสำรวจ, หนีปีศาจ, ทำสัญญากับผี และตอบเลขทุกห้องให้ถูกต้องเพื่อชนะ

## วิธีรัน

ต้องมี Node.js (แนะนำ v18+)

```bash
# ติดตั้ง dependency (มีแค่ ws)
pnpm install

# รัน server
node server/server.js
```

จากนั้นเปิดเบราว์เซอร์ไปที่ **http://localhost:3799**

> พอร์ตเปลี่ยนได้ด้วย `PORT=xxxx node server/server.js` (ค่าเริ่มต้น 3799)

- **สร้างห้อง**: ใส่ชื่อ, เลือกขนาดบอร์ด (6/7/8), ตั้ง "คีย์ห้อง" (รหัสลับ), เลือกความเร็วปีศาจ (เดินทุก 1 / 2 / 3 รอบ — ค่าเริ่มต้น 2) → ได้ "รหัสห้อง" ออกมา
- **เข้าร่วม**: ใส่ชื่อ + รหัสห้อง + คีย์ห้อง
- โฮสต์กด **เริ่มเกม** เมื่อมีผู้เล่นอย่างน้อย 2 คน

## วิธีเล่น (สรุป)

> ในเกมมีปุ่ม **📖 วิธีเล่น** ทั้งหน้าแรกและระหว่างเล่น

- บอร์ดสุ่ม 6×6–8×8; ห้องทะลุได้มีเลข 1–99 ไม่ซ้ำ; ห้องตัน = กำแพง
- **ประตูสุ่ม**: ห้องที่ติดกันอาจมีหรือไม่มีประตู (ประตูเปิดทั้งสองฝั่งเสมอ) และทุกห้องเดินถึงกันได้หมด
- เดินทีละ 1 ช่องต่อตา ผ่านประตูเท่านั้น แล้วกด **จบตา** — แต่ละตามีเวลา **120 วินาที** (หมดเวลาจบตาให้อัตโนมัติ)
- เมื่อเดินเข้าห้องจะรู้เลขห้องนั้น + เห็นประตู/กำแพงของห้อง
- **ชนะ**: เดินเข้าห้องชนะ (ซ่อนอยู่) แล้วตอบเลขของทุกห้องให้ถูกต้องครบ → ชนะทันที; ตอบผิด → ห้องชนะย้ายไปห้องใหม่
- **ปีศาจ** 1 ตัว มองไม่เห็น เดินผ่านประตู เริ่มเดินรอบ 2 (ทุก 1–3 รอบตามที่โฮสต์ตั้ง); เดินเข้าห้องเดียวกับปีศาจ = ตายกลายเป็นผี
  - ระบบ **เตือนทุกคน (ไม่บอกชื่อ)** เมื่อปีศาจอยู่ในระยะ 1 ช่องรอบตัวผู้เล่นคนใดคนหนึ่ง (รวมทแยง)
  - **ไม่มีใครรู้ว่าใครตาย** จนกว่าจะเจอตัวกัน หรือเกมจบ
  - ผู้รอดชีวิตตายหมด → **ปีศาจชนะ** เกมจบทันที
- **ผี**: ชนะเองไม่ได้ แต่เดินต่อได้ (ทะลุกำแพงและประตูปิด), เห็นปีศาจเสมอ, และเมื่อเจอผู้เล่นจะ **ทำสัญญา** ได้: ให้เลขห้อง / แผนที่ทางเดิน (ประตู) / ตำแหน่งปีศาจ แลกกับ "ชนะร่วม" หรือ "สัญญาชุบ" (ใบชุบใบแรกของผู้เล่นต้องชุบผีคนนั้น)
- **ห้องคำถาม**: ตอบคำถามความรู้ทั่วไป (4 ตัวเลือก) ถูกได้ไอเทมสุ่ม, ผิด (หรือหมดเวลา) ห้องกลายเป็นห้องธรรมดา
- **เจอกัน**: เกมหยุดให้คุยส่วนตัว (แชทเรียลไทม์) — ผู้เล่นที่ยังมีชีวิต **แชร์ข้อมูลห้องให้กัน** หรือ **เสนอแลก** (แลกจริงเมื่อยืนยันทั้งคู่, ปฏิเสธได้); จะเป็นพันธมิตรกันก็ตกลงกันเองในแชท

## ตัวช่วยระหว่างเล่น

- **📝 สมุดจด (เห็นคนเดียว)**: จดเดาเลข/กำแพงบนช่องที่ยังไม่รู้ + กล่องโน้ตอิสระ — ตอนยื่นคำตอบจะเติมค่าที่จดไว้ให้อัตโนมัติ (เก็บในเบราว์เซอร์ของเครื่องนั้น)
- **กลับเข้าเกมได้**: รีเฟรชหรือเน็ตหลุด กลับมาเปิดหน้าเว็บเดิมภายใน 3 นาทีจะเข้าเกมต่อ (ระหว่างหลุด ตาจะถูกข้าม และคนอื่นเห็นป้าย "📴 หลุด")
- **บอกขั้นตอน + สัญลักษณ์**: แถบบอกตาบอกว่าตอนนี้ต้องทำอะไร พร้อมตัวนับถอยหลัง และกล่องอธิบายสัญลักษณ์บนกระดาน
- **หน้าสรุปตอนจบเกม**: สถิติทุกคน (รอด/ตาย, เข้าห้องกี่ห้อง, รู้เลขกี่ห้อง, ก้าว, คำถาม, ไอเทม ฯลฯ), สัญญากับผี และเฉลยกระดานทั้งหมด

ดูรายละเอียด + ข้อตัดสินใจออกแบบทั้งหมดใน [DESIGN.md](DESIGN.md)

## Deploy (push ขึ้น GitHub → รันบนคลาวด์)

โปรเจกต์นี้ **ไม่มี build step** และ client ต่อ WebSocket ไปยัง origin เดียวกับหน้าเว็บ จึง deploy บน PaaS ที่รองรับ WebSocket (Render, Railway, Fly.io, Heroku ฯลฯ) ได้ง่าย:

1. อัปโหลดขึ้น GitHub:
   ```bash
   git init
   git add .
   git commit -m "Deadly Dungeon"
   git remote add origin <repo-url>
   git push -u origin main
   ```
   (`.gitignore` เตรียมไว้แล้ว — `node_modules/` จะไม่ถูก commit)
2. สร้าง service บนแพลตฟอร์มที่เลือก:
   - **Build command**: `npm install` (หรือ `pnpm install`)
   - **Start command**: `npm start` (เทียบเท่า `node server/server.js`)
   - **Port**: ใช้ `PORT` จาก environment variable ได้เลย — server อ่าน `process.env.PORT` อัตโนมัติ (ค่าเริ่มต้น 3799)
3. เปิด URL ที่ได้ → สร้างห้อง แล้วส่ง "รหัสห้อง + คีย์ห้อง" ให้เพื่อน

> server รับ WebSocket ที่ path `/ws` บน origin เดียวกัน ไม่ต้องตั้งค่าเพิ่ม และ bind ทุก interface (`0.0.0.0`) เป็นค่าเริ่มต้นของ Node อยู่แล้ว

## โครงสร้าง

```
deadly-dungeon/
├── server/
│   ├── server.js        # HTTP + WebSocket + ห้อง/lobby + กลับเข้าเกม + ตัวจับเวลา
│   ├── game.js          # เกมเอนจิน (บอร์ด/ประตู/เดิน/ปีศาจ/อีเวนต์/ไอเทม/สัญญา/แชร์-แลก/จับเวลา/สรุปผล)
│   ├── questions.js     # โหลดคลังคำถาม (+fallback)
│   └── questions.json   # คลังคำถาม 120 ข้อ
├── public/
│   ├── index.html
│   ├── style.css
│   └── app.js           # client (vanilla JS, ไม่มี build)
├── test.js              # smoke test (engine + WebSocket)
├── test2.js             # unit test (ไอเทม/ปีศาจ/ผี/สัญญา/คำถาม)
├── DESIGN.md            # กติกา + ข้อตัดสินใจออกแบบ
└── package.json
```

## เทคโนโลยี

- **Server**: Node.js + `ws` (server-authoritative, state อยู่ฝั่ง server)
- **Client**: HTML/CSS/JS แบบไม่มี build step — server ตัวเดียวเสิร์ฟทุกอย่าง
- โปรโตคอล: WebSocket; server ส่ง "state แบบ sanitize ตามผู้เล่น" หลังทุกการเปลี่ยนแปลง (ข้อมูลลับ เช่น ใครตาย/ตำแหน่งปีศาจ จะไม่ถูกส่งให้คนที่ไม่ควรรู้)

node test.js    # board gen + lobby/start/move/turn + win
